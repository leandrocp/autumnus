# Custom Formatters

Write your own formatter when the built-in ones don't produce the output you need. Common reasons:

- wrap output with custom HTML
- emit Markdown, LaTeX, or structured data
- add annotations, data attributes, or extra classes
- feed Lumis tokens into an existing rendering pipeline

## Rust

Implement the [`Formatter`](https://docs.rs/lumis/latest/lumis/formatters/trait.Formatter.html) trait. A formatter declares the language it uses, then renders the projected `LineView`.

```rust
use lumis::{
    formatters::Formatter,
    formatters::html::{closing_tags, open_code_tag, open_pre_tag},
    highlight::LineView,
    languages::Language,
    themes,
};
use std::io::{self, Write};

struct MinimalHtmlFormatter {
    language: Language,
    theme: Option<themes::Theme>,
}

impl Formatter for MinimalHtmlFormatter {
    fn language(&self) -> Language {
        self.language
    }

    fn render(&self, view: &LineView, output: &mut dyn Write) -> io::Result<()> {
        open_pre_tag(output, None, self.theme.as_ref())?;
        open_code_tag(output, &self.language)?;
        for line in &view.lines {
            for span in &line.spans {
                write!(output, "{}", span.text)?;
            }
        }
        closing_tags(output)?;
        Ok(())
    }
}
```

### Supporting LineView decorations

Decorators add things that are not syntax tokens: line highlights, signs, gutter text, virtual text, and inline span decorations. A formatter that wants those should render a `LineView`, not just the raw token stream.

The split is deliberate:

- decorators decide what extra data exists
- formatters decide how that data looks

The flow is:

```text
source + language + decorators
  -> LineViewBuilder::new().source(...).language(...).decorators(...).build()
  -> your formatter's HTML, ANSI, JSON, or review UI
```

At render time, handle the line data:

- `Line.line_highlights` for whole-line state such as selected lines or review notes.
- `Line.signs` for short status markers beside a line.
- `Line.gutter_text` for optional custom gutter labels.
- `Line.virtual_text` for overlays attached to display columns.
- `Span.style` and `Span.decoration_kinds` for inline decorations such as rainbow brackets or custom review markers.

Built-in decorator labels live in `lumis::highlight::annotation_kinds`. The built-in decorator today is rainbow brackets. Use your own strings for custom decorator labels.

```rust
use lumis::highlight::annotation_kinds;

if span.decoration_kinds.iter().any(|kind| kind.starts_with(annotation_kinds::RAINBOW_BRACKET_PREFIX)) {
    // Render built-in rainbow-bracket styling.
}
```

In practice, a custom formatter adds the decorators it needs in `prepare_line_view`, then renders the resulting `LineView`. The full example renders a review card with line numbers from `Line.line_number`, inline TODO/FIXME markers, and an annotation rail.

```rust
use lumis::{
    formatters::Formatter,
    formatters::html,
    highlight::{
        DecoratorContext, DecorationOutput, LineHighlight, LineView, LineViewBuilder,
        LineViewDecorator, StylePatch,
    },
    languages::Language,
};
use std::io::{self, Write};

struct TodoDecorator;

impl LineViewDecorator for TodoDecorator {
    fn run(&self, context: DecoratorContext<'_>, output: &mut DecorationOutput) {
        for (index, line) in context.source().split('\n').enumerate() {
            if line.contains("TODO") {
                output.line_highlights.push(LineHighlight {
                    line: index + 1,
                    kind: Some("todo.line".to_string()),
                    class: Some("has-todo".to_string()),
                    style: StylePatch {
                        bg: Some("#2a2112".to_string()),
                        ..StylePatch::default()
                    },
                });
            }
        }
    }
}

struct ReviewHtmlFormatter {
    language: Language,
    todo_decorator: TodoDecorator,
}

impl Formatter for ReviewHtmlFormatter {
    fn language(&self) -> Language {
        self.language
    }

    fn prepare_line_view<'a>(&self, source: &'a str, builder: &mut LineViewBuilder<'a>) {
        let mut decoration_output = DecorationOutput::default();
        self.todo_decorator
            .run(DecoratorContext::new(source), &mut decoration_output);

        builder.decoration_output(decoration_output);
    }

    fn render(&self, view: &LineView, output: &mut dyn Write) -> io::Result<()> {
        writeln!(output, "<section class=\"review-card\">")?;
        writeln!(output, "<pre class=\"review-code\"><code>")?;
        for line in &view.lines {
            let class = line
                .line_highlights
                .first()
                .and_then(|highlight| highlight.class.as_deref())
                .unwrap_or("line");

            write!(output, "<span class=\"{}\">", html::escape(class))?;
            write!(output, "<span class=\"line-number\">{}</span>", line.line_number)?;
            for span in &line.spans {
                write!(output, "{}", html::escape(&span.text))?;
            }
            writeln!(output, "</span>")?;
        }
        writeln!(output, "</code></pre>")?;
        writeln!(output, "<aside class=\"review-notes\">...</aside>")?;
        writeln!(output, "</section>")?;

        Ok(())
    }
}
```

If your formatter uses `highlight_iter()` directly, it can still render syntax highlighting. It just will not see line decorations or inline decorator decorations.

The full version, including CSS, inline `HighlightDecoration` rendering, and annotation extraction, is in [`crates/lumis/examples/custom_formatter_decorator.rs`](https://github.com/leandrocp/lumis/blob/main/crates/lumis/examples/custom_formatter_decorator.rs).

See [LineView Decorations](/usage/line-view-decorations) for the custom decorator API.

## JavaScript

Pass an object with `language` and `format(source)`. Inside `format()`, use the sync free functions `highlightIter()` or `highlightEvents()` imported from `@lumis-sh/lumis`.

```ts
import {createHighlighter, highlightIter} from '@lumis-sh/lumis'
import type {Formatter} from '@lumis-sh/lumis/formatters'
import {openPreTag, openCodeTag, closingTags, spanInline} from '@lumis-sh/lumis/formatters/html'
import rust from '@lumis-sh/lumis/langs/rust'
import dracula from '@lumis-sh/themes/dracula'

const hl = await createHighlighter({languages: [rust]})

const formatter: Formatter = {
  language: rust,
  format(source) {
    const parts: string[] = []

    parts.push(openPreTag({preClass: 'docs-demo', theme: dracula}))
    parts.push(openCodeTag(this.language))

    highlightIter(source, this.language, dracula, (text, language, _range, scope, _style) => {
      if (scope) {
        parts.push(spanInline(text, {language, scope, theme: dracula}))
      } else {
        parts.push(text)
      }
    })

    parts.push(closingTags())
    return parts.join('')
  },
}

const html = hl.highlight('fn main() {}', formatter)
```
