# CSS Builder

Lumis ships a pre-built CSS file for every theme (see [CSS Theme Files](/themes/css-files)). The CSS builder produces the same kind of stylesheet at runtime, so you can change the selectors, nest the rules under a parent, override the background, or append your own declarations.

Reach for it when the bundled files do not fit, for example when you scope a dark theme under a `data-theme` attribute, embed the CSS in a `<style>` tag, or match a wrapper element that is not `pre.lumis`.

## Default output

With no options, the builder produces the same stylesheet as the bundled file for that theme.

```js
import {buildCss} from '@lumis-sh/themes'
import dracula from '@lumis-sh/themes/dracula'

const css = buildCss(dracula)
```

  </TabItem>
  <TabItem value="rust" label="Rust">

```rust
use lumis::themes;

let theme = themes::get("dracula").unwrap();
let css = themes::CssBuilder::new(&theme).build();
```

  </TabItem>
  <TabItem value="elixir" label="Elixir">

```elixir
css = Lumis.Theme.build_css!("dracula")
```

  </TabItem>
</Tabs>

The theme can be a bundled one or one you loaded yourself. In JavaScript, pass any theme object (an import from `@lumis-sh/themes` or your own JSON). In Rust, pass a `&Theme` from `themes::get` or `themes::from_json`. In Elixir, pass a bundled theme name or a `Lumis.Theme` struct from `Lumis.Theme.from_json/1`.

## Options

JavaScript uses camelCase option names. Rust and Elixir use snake_case. They map one to one.

| Option | Default | What it changes |
| --- | --- | --- |
| `enableItalic` / `enable_italic` | `true` | When `false`, `font-style: italic` is dropped. A scope whose only styling is italic produces no rule at all. |
| `selectorPrefix` / `selector_prefix` | `""` | Text placed in front of every selector, both the base rule and each token rule. Use it to scope the whole stylesheet under a parent selector. |
| `preSelector` / `pre_selector` | `"pre.lumis"` | The selector for the base code block rule. Change it to match the element your wrapper emits. |
| `scopeTokens` / `scope_tokens` | `false` | When `true`, token rules are nested under the base selector, so `.keyword` becomes `.lumis .keyword`. This keeps the token classes from matching unrelated markup. |
| `background` | theme's `normal` background | Sets `background-color` on the base rule. Useful for pointing at a CSS variable instead of a fixed color. |
| `baseRules` / `base_rules` | none | Extra `property, value` declarations appended to the base rule, such as `padding` or `border-radius`. |

In Rust, `base_rule` is a method you call once per declaration. In JavaScript and Elixir, `baseRules` / `base_rules` takes a list of pairs.

## Scope a dark theme under a selector

Say you want a dark theme to apply only inside `html[data-theme="dark"]`, with a rounded background that reads its color from a CSS variable. That looks like this:

<Tabs groupId="runtime" queryString="lang" defaultValue="javascript">
  <TabItem value="javascript" label="JavaScript">

```js
import {buildCss} from '@lumis-sh/themes'
import githubDark from '@lumis-sh/themes/github_dark'

const css = buildCss(githubDark, {
  selectorPrefix: 'html[data-theme="dark"] ',
  preSelector: '.lumis',
  scopeTokens: true,
  background: 'var(--code-background)',
  baseRules: [
    ['border-radius', '0.375rem'],
    ['padding', '1rem'],
  ],
})
```

  </TabItem>
  <TabItem value="rust" label="Rust">

```rust
use lumis::themes;

let theme = themes::get("github_dark").unwrap();

let css = themes::CssBuilder::new(&theme)
    .selector_prefix("html[data-theme=\"dark\"] ")
    .pre_selector(".lumis")
    .scope_tokens(true)
    .background("var(--code-background)")
    .base_rule("border-radius", "0.375rem")
    .base_rule("padding", "1rem")
    .build();
```

  </TabItem>
  <TabItem value="elixir" label="Elixir">

```elixir
css =
  Lumis.Theme.build_css!("github_dark",
    selector_prefix: ~s(html[data-theme="dark"] ),
    pre_selector: ".lumis",
    scope_tokens: true,
    background: "var(--code-background)",
    base_rules: [
      {"border-radius", "0.375rem"},
      {"padding", "1rem"}
    ]
  )
```

  </TabItem>
</Tabs>

## What the output looks like

The result starts with a comment carrying the theme name and revision, then the base rule for `preSelector`, then one rule per highlight scope. Scope names with dots become dashes, so `tag.attribute` turns into `.tag-attribute`.

The `normal` scope is the exception. It sets the block's base color and background, which the base rule already carries and every token inherits, so it is not emitted as its own `.normal` rule.

The options above produce CSS shaped like this (colors trimmed for brevity):

```css
/* github_dark
 * revision: 5620bfd
 */

html[data-theme="dark"] .lumis {
  color: #e6edf3;
  background-color: var(--code-background);
  border-radius: 0.375rem;
  padding: 1rem;
}
html[data-theme="dark"] .lumis .keyword {
  color: #ff7b72;
}
html[data-theme="dark"] .lumis .string {
  color: #a5d6ff;
}
```

## Errors

In Elixir, `build_css/2` returns `{:ok, css}` or `{:error, reason}`, and `build_css!/2` raises instead. An unknown theme name returns `{:error, :not_found}`, and an invalid option returns the validation error. In Rust and JavaScript the builder works from a theme value you already loaded, so there is no lookup to fail.

## Other runtimes

Java and the CLI do not expose the builder. They read the pre-built stylesheets instead, which cover the default output. See [CSS Theme Files](/themes/css-files) for how to load those.
