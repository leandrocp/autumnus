# Elixir

## When you want explicit error handling

Use [`highlight/2`](https://hexdocs.pm/lumis/Lumis.html#highlight/2) when invalid user input, formatter options, or language detection should stay in the normal control flow.

```elixir
case Lumis.highlight(source, formatter: {:html_inline, language: "elixir"}) do
  {:ok, html} -> html
  {:error, reason} -> handle_error(reason)
end
```

`highlight/2` returns `{:ok, output}` or `{:error, reason}`.

## When you want the highlighted output directly

Use [`highlight!/2`](https://hexdocs.pm/lumis/Lumis.html#highlight!/2) when failures should raise immediately, such as in scripts, trusted internal code, or examples.

```elixir
html = Lumis.highlight!(source, formatter: {:html_inline, language: "elixir"})
```

`highlight!/2` returns the highlighted output or raises.

## Language selection

Elixir accepts several forms:

```elixir
Lumis.highlight!(code, formatter: {:html_inline, language: "elixir"})
Lumis.highlight!(code, formatter: {:html_inline, language: ".ex"})
Lumis.highlight!(code, formatter: {:html_inline, language: "lib/my_app.ex"})
Lumis.highlight!(code)
```

Omitting `language` from the formatter enables auto-detection.

## Parser loading

Lumis highlights only what you have loaded. `Lumis.highlight/2` raises for a
language that is not loaded, and a language injected inside a document is left
unhighlighted unless it was loaded too, so load a document's injected languages
as well as its own.

Parser WASM is packaged with matching queries and integrity metadata, then
cached in the platform user cache directory. It first checks release-local
`priv/wasm`, so production releases do not need a runtime download.

```elixir
:ok = Lumis.Languages.load(["markdown", "elixir", "json"])
:ok = Lumis.Languages.load(:all)
```

Configure which languages a release bundles, then run the task. Configuration is
the only place the set is defined, so a release cannot disagree with development:

```elixir title="config/prod.exs"
config :lumis, bundled_languages: ~w(elixir html javascript css)
```

```bash title="Bundle parsers into the release"
MIX_ENV=prod mix do compile, lumis.languages.cache, release
```

Use `bundled_languages: :all` to bundle the whole catalog, `--force` to replace
files that already verify, and `--output` to write somewhere other than
`priv/wasm`.

```elixir
:ok = Lumis.Languages.load(["elixir", "html", "javascript", "css"])
```

Load every language you expect to render during application startup — see
[Load what you intend to highlight](/advanced/wasm-and-cdn#load-what-you-intend-to-highlight).
Wasmtime persists compiled modules across VM restarts. Set
`LUMIS_WASM_CACHE_DIR` to override the parser and compiled-module cache root.

A custom `:wasm_resolver` application setting can return `{:ok, bytes}`,
`{:file, path}`, or a URL:

```elixir
config :lumis, :language_package_resolver, fn language ->
  {:file, Path.join("/app/wasm", "#{Path.basename(language.package_name)}.language.json")}
end

config :lumis, :wasm_resolver, fn parser ->
  {:file, Path.join("/app/wasm", "#{parser.wasm_name}.wasm")}
end
```

## Discover supported languages and themes

```elixir
Lumis.available_languages()
Lumis.available_themes()
Lumis.Theme.get("github_light")
```

See [`Lumis`](https://hexdocs.pm/lumis/Lumis.html) and [`Lumis.Theme`](https://hexdocs.pm/lumis/Lumis.Theme.html) on HexDocs.

## Phoenix and LiveView

Highlighted HTML must be rendered as raw HTML in templates.

```elixir
code = Lumis.highlight!(source, formatter: {:html_inline, language: "elixir"})
```

```heex
{Phoenix.HTML.raw(@code)}
```

For linked CSS output, also mount a theme stylesheet through `Plug.Static` as shown in [CSS Theme Files](/themes/css-files).

## Light/dark mode

See [Light/Dark Mode](/recipes/light-dark) for three approaches to theme switching (CSS `light-dark()`, media queries, and manual toggle).

## Custom themes

```elixir
{:ok, theme} = Lumis.Theme.from_file("/path/to/theme.json")
{:ok, theme} = Lumis.Theme.from_json(theme_json)
```

Then pass the resulting theme struct into the formatter options.

## Validation

```elixir
# validate options before passing to highlight
Lumis.validate_options!(formatter: {:html_inline, language: "elixir", theme: "dracula"})

# inspect defaults
Lumis.default_options()
```

Use `validate_options!/1` when your app exposes formatter options to users (e.g., config files, admin panels). It raises on invalid values.
